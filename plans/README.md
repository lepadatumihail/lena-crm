## Findings considered and rejected (do not re-audit)

- **Dialog local-time `Date` construction** (`viewing-dialog.tsx:122`, `appointment-dialog.tsx:132`): correct by design — the browser is the agent's timezone; storing the UTC instant is right. The server-side formatting of those instants was the bug (plan 002).
- **`revalidatePath("/clients")` as a *visible* staleness bug**: the bundled Next 16 docs (`revalidatePath.md`, Good-to-know) state server-action revalidation currently refreshes all previously-visited pages, and these routes are fully dynamic — so no user-visible staleness today. Fixed as latent-correctness hygiene in plan 005, impact honestly LOW.
- **ICS escaping injection theory**: `esc()` in `src/lib/ics.ts:10-16` already neutralizes CRLF/semicolon/comma — no property-injection path. Folding (plan 004) is a compatibility fix, not an injection fix.
- **`Cache-Control: public` on the feed as a HIGH cross-tenant leak**: shared caches are URL-keyed; serving a cached copy requires the secret URL. Downgraded to hardening; one-line fix included in plan 004.
- **`x-forwarded-host` as session leakage**: wrong mechanism (cookies don't ride redirects to other origins); the real risk is open-redirect/phishing, and Vercel controls that header on its platform. Kept inside the unselected F5.
- **`addDocument` cross-tenant "pollution visible to the victim"**: wrong — RLS (`agent_id = auth.uid()`) hides the attacker's row from the victim entirely. Residual (UUID probing, own-tenant junk) handled in plan 003.
- **Concurrent `syncNotifications` double-inserts**: impossible — `notifications_agent_dedupe_idx` unique index + upsert. Only the wasted round-trips were real (plan 002 adds an in-flight guard).
- **`verifyFeedToken` timing-compare on base64url strings**: functionally correct (ASCII alphabet); idiom tightened as a rider in plan 004, not a vulnerability.
- **npm audit**: 2 moderate advisories, both via `next`'s own postcss pinning (`next 9.3.4-canary.0 – 16.3.0-canary.5`); no critical/high in reachable code. Action: pick up the patched Next release when published; nothing to plan.
- **framer-motion bundle weight**: imported by exactly 3 landing components, zero app-shell leakage (verified); `next/dynamic` wrapping not worth it absent a landing-perf goal.
- **`email_accounts`/`email_templates`/`scheduled_emails` as dead schema**: intentional — deferred v2 per README; now the subject of plan 007.
- **`getNeedsAttention` server-clock day boundary**: accepted limitation (documented in plan 002, Step 5) — fixing it properly needs a persisted agent timezone; revisit only if agents report wrong Home dates.
- **`Number("0x10")` accepted by `numericString`**: harmless quirk (valid number, ≥ 0); not worth a rule.
